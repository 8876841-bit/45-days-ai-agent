## Day 1：Token 与 LLM 全景直觉

大家好，今天是我学习 AI Agent 基础的第一天。

今天我最大的收获是：大模型不是直接读文字，而是先把文字切成 token。

比如我输入一句话：

```text
我要在45天内掌握 AI Agent
```

人在看的时候，是一整句话。  
但模型看到的不是这句话本身，而是 tokenizer 切出来的一段段 token。

token 可以是一个词、一个字、一个英文片段，也可能是空格、标点、代码里的括号和换行。

这些 token 接下来会变成数字 ID，再通过 embedding 变成向量。

也就是说，模型不是在中文或英文里直接理解世界，而是在一个数字空间里处理这些 token。

今天我还建立了一条最基础的流程：

```text
文本 -> token -> embedding -> attention -> logits -> sampling -> 输出
```

这让我第一次觉得，大模型没有那么玄。

它不是一下子写出完整答案，而是根据前面的上下文，不断预测下一个最合适的 token。

Day 1 的总结是：

**LLM 的第一层直觉，是文本先被切成 token，模型围绕 token 做预测。**

今天最重要的三句话是：

第一，大模型不是直接读文字，而是读 token。  
第二，token 会被变成向量，进入模型计算。  
第三，大模型是在不断预测下一个 token。

## Day 2：Self-Attention 与 QKV

大家好，今天是我学习 AI Agent 基础的第二天。

昨天我理解了 token，今天我开始理解 self-attention。

一开始看到公式我很懵：

```text
Attention(Q, K, V) = softmax(QK^T / sqrt(d_k))V
```

后来我把它拆成三个问题：

像不像。  
看多少。  
混合成什么。

模型会先计算每个 token 和其他 token 的相关性，这个原始分数叫 scores。

scores 经过 softmax 之后，会变成 weights。

weights 就是每个 token 在更新自己时，应该看谁、看多少。

最后模型会按照这些注意力比例，把其他 token 的信息混进来，形成新的向量。

所以原来的 token 不再是孤立的自己，而是带上了上下文信息。

今天我记住了一句话：

```text
scores 是像不像，weights 是看多少，output 是混合后的新表示。
```

Day 2 的总结是：

**Self-Attention 会让每个 token 看一遍上下文，决定谁更重要，再把重要信息混进自己的新表示里。**

今天最重要的三句话是：

第一，scores 表示 token 之间像不像。  
第二，weights 表示每个 token 看谁、看多少。  
第三，output 是混合上下文后的新表示。

## Day 3：PyTorch 与 Mini Transformer 的 Shape

大家好，今天是我学习 AI Agent 基础的第三天。

前两天我理解了 token 和 self-attention，今天我开始从 NumPy 进入 PyTorch。

今天的重点不是训练一个大模型，而是搞懂数据在模型里到底长什么样。

我以前看到 batch、seq、hidden 这些词会很迷糊。今天终于把它们对应上了。

batch 是一次处理多少条样本。  
seq 是每条样本有多少个 token。  
hidden 是每个 token 的向量维度。

在 PyTorch 里，输入通常会先是：

```text
[batch, seq]
```

这表示 token id。

经过 embedding 之后，会变成：

```text
[batch, seq, hidden]
```

这表示每个 token 都变成了一个向量。

接下来，模型会用 Linear 层把这些向量投影成 Q、K、V。

也就是：

```text
Q = 我在找什么
K = 我有什么标签
V = 我的实际内容
```

今天我还理解了 multi-head attention。

可以先把它理解成：不是只用一双眼睛看一句话，而是用多双眼睛从不同角度看。

Day 3 的总结是：

**如果 Day 2 是理解 attention 在算什么，Day 3 就是理解 attention 在代码里怎么跑。**

今天最重要的三句话是：

第一，batch 是一次处理多少条样本。  
第二，seq 是每条样本有多少个 token。  
第三，hidden 是每个 token 的向量维度。

## Day 4：最小字符级语言模型

大家好，今天是我学习 AI Agent 基础的第四天。

前三天我理解了 token、attention 和 PyTorch 里的 shape。

到了第四天，我开始训练一个最小的字符级语言模型。

这个模型很小，不是 ChatGPT 那种大模型。但它做的事情，和大模型的底层训练目标是相通的：

```text
根据前面的内容，预测下一个字符。
```

比如训练文本里有：

```text
hello world
```

模型看到 `hell`，就要学着预测下一个字符可能是 `o`。

真正的大语言模型预测的是下一个 token，我今天做的是字符级版本。

今天我第一次更具体地理解了训练循环：

输入文本。  
模型预测。  
和正确答案对比。  
计算 loss。  
根据 loss 调整参数。  
重复很多次。

loss 可以理解成模型的错题分数。

loss 下降，说明模型在学习。

Day 4 的总结是：

**语言模型最基础的训练任务，就是看前文，预测下一个 token。**

今天最重要的三句话是：

第一，语言模型的核心任务是预测下一个 token。  
第二，loss 衡量模型错得有多离谱。  
第三，训练就是不断用错误反馈调整参数。

## Day 5：残差连接

大家好，今天是我学习 AI Agent 基础的第五天。

今天我学的是残差连接。

一开始我看到 residual connection，感觉它只是把输入加回输出：

```text
output = x + f(x)
```

看起来很简单，甚至有点奇怪。

后来我理解了，它的作用不是让模型偷懒，而是给信息和梯度留一条更顺的路。

如果没有残差连接，网络一层一层往下传，信息可能会被改得越来越乱，梯度也可能慢慢变弱。

残差连接就像每一层都保留一份原始信息。

新加工的信息可以加上去，但原来的信息不容易丢。

我今天最喜欢的理解是：

**普通网络像是在学完整答案，残差网络像是在学需要改哪里。**

Transformer 里 attention 后面有残差，FFN 后面也有残差。

Day 5 的总结是：

**深度模型能训练得动，不只是因为 attention 强，也因为残差连接让信息流动更稳定。**

今天最重要的三句话是：

第一，残差连接就是把输入直接加回输出。  
第二，它让信息和梯度有更顺的通路。  
第三，模型不必从零学习全部变换，只需要学习在原基础上改什么。

## Day 6：Tokenizer 与上下文成本

大家好，今天是我学习 AI Agent 基础的第六天。

今天我重新回到 tokenizer，但这次关注的是成本和上下文。

第一天我只是知道，大模型会把文字切成 token。

今天我更具体地意识到：token 不只是技术概念，它直接影响成本、速度和上下文长度。

同样一句话，中文、英文、代码、Markdown 切出来的 token 数可能完全不一样。

代码里的换行、缩进、括号、引号，也都会占 token。

这让我意识到：

**模型处理的不是我们眼里的字符数，而是 tokenizer 切出来的 token 数。**

token 越多，通常意味着成本越高，速度越慢，上下文压力越大。

今天我还理解了上下文窗口。

它可以理解成模型一次能看到的工作台。

system prompt、用户问题、历史对话、工具返回结果、RAG 检索内容，全部都要放进这个工作台里。

工作台不是无限大的。

Day 6 的总结是：

**token 是大模型世界里的基本预算单位。它影响钱、速度和上下文容量。**

今天最重要的三句话是：

第一，模型真正处理的是 token，不是字符。  
第二，token 越多，成本越高，速度越慢。  
第三，好的 Agent 必须管理上下文，而不是把所有东西都塞给模型。

## Day 7：Embedding 与语义检索

大家好，今天是我学习 AI Agent 基础的第七天。

今天我学的是 Embedding 和语义检索。

第一天我已经知道，token 会被变成向量。今天我更进一步理解了：向量不仅可以给模型内部计算用，也可以拿来做搜索。

以前我们搜索东西，更多是靠关键词。

比如我搜“AI Agent”，系统可能只会找包含这两个词的内容。

但语义检索不是只看字面有没有这个词，而是看两段话的意思像不像。

比如：

```text
怎么让 AI 调用工具？
如何实现模型的 function calling？
```

这两句话字面不一样，但意思很接近。

如果用 embedding，它们在向量空间里的位置就会比较近。

今天我最重要的直觉是：

**Embedding 是把文本放进一个语义地图里。**

RAG 的底层逻辑也和它有关。

先把文档切块，再把每一块变成 embedding。用户提问时，也把问题变成 embedding，然后找最相近的文档块。

Day 7 的总结是：

**RAG 的本质不是让模型记住所有文档，而是先找相关内容，再让模型回答。**

今天最重要的三句话是：

第一，Embedding 是把文本变成语义向量。  
第二，语义检索不是看关键词，而是看意思像不像。  
第三，RAG 是先检索，再回答。

## Day 8：KV Cache 与长上下文

大家好，今天是我学习 AI Agent 基础的第八天。

今天我学的是 KV Cache 和长上下文。

一开始我看到 KV Cache 这个词挺懵。后来把它和 attention 连起来，就清楚多了。

在 attention 里，每个 token 都会生成 Q、K、V。

Q 是我在找什么。  
K 是我有什么标签。  
V 是我的实际内容。

模型生成回答时，不是一次性把整段话写完，而是一个 token 一个 token 往后生成。

如果每生成一个新 token，都重新计算前面所有 token 的 K 和 V，就很浪费。

所以 KV Cache 的作用就是：

**把前面 token 的 K 和 V 缓存起来，下次直接用。**

这就像做饭时，前面已经切好的菜，不需要每一步都重新切。

今天我还理解了 prefill 和 decode。

prefill 是先读完整个输入。  
decode 是一个 token 一个 token 地生成回答。

KV Cache 主要是在 decode 阶段帮忙加速。

但 KV Cache 不是免费午餐。

上下文越长，需要缓存的 K 和 V 越多，也会占内存和显存。

Day 8 的总结是：

**KV Cache 能减少重复计算，但长上下文本身依然有成本。**

今天最重要的三句话是：

第一，KV Cache 会缓存前面 token 的 K 和 V。  
第二，prefill 是读输入，decode 是逐个生成输出。  
第三，长上下文依然有成本，Agent 必须学会上下文管理。

## Day 9：采样策略

大家好，今天是我学习 AI Agent 基础的第九天。

今天我学的是采样策略。

也就是：模型已经算出了下一个 token 的概率，那它到底应该选哪一个？

以前我以为模型就是选概率最高的词。

但今天我发现，事情没这么简单。

如果永远选概率最高的，输出会很稳定，但也可能很死板。

如果允许它从多个候选里抽样，输出会更灵活，但也可能更发散。

今天我重点理解了几个参数。

temperature 可以理解成模型的大胆程度。

temperature 低，模型更保守。  
temperature 高，模型更开放。

top-k 是只从概率最高的前 k 个 token 里选。

top-p 是从累计概率达到某个范围的 token 里选。

今天我最大的收获是：

**模型不是只有一个答案，它是在概率分布里做选择。**

这也解释了为什么同一个 prompt，有时回答很稳定，有时回答更发散。

Day 9 的总结是：

**采样策略决定模型从概率分布里如何选择下一个 token。**

今天最重要的三句话是：

第一，模型输出前会得到一组候选 token 的概率分布。  
第二，temperature 控制保守还是发散。  
第三，top-k 和 top-p 控制候选范围。

## Day 10：第一阶段复盘

大家好，今天是我学习 AI Agent 基础的第十天。

今天我没有继续学新概念，而是做第一阶段复盘。

这十天最重要的变化是，我对大模型的理解从“它好像会思考”，变成了一条比较清楚的链路。

文本先被 tokenizer 切成 token。  
token 被转换成向量。  
向量进入 Transformer。  
attention 让每个 token 看上下文。  
残差连接和 LayerNorm 让深层网络更稳定。  
模型最终输出下一个 token 的概率分布。  
采样策略决定真正选哪个 token。  
然后这个过程不断重复，生成完整回答。

现在我再看大模型，它不再是一个完全的黑盒。

我还没有完全懂它，但至少知道每个关键部件大概在什么位置，解决的是什么问题。

这十天还有一个收获：做 Agent 不能只会写 prompt。

因为 Agent 的稳定性、成本和能力边界，都和这些底层概念有关。

Day 10 的总结是：

**大模型不是魔法，而是一套围绕 token 展开的预测系统。**

今天最重要的三句话是：

第一，大模型的核心是围绕 token 做预测。  
第二，attention 让 token 能结合上下文。  
第三，Agent 的工程能力，建立在理解模型边界之上。

## Day 11：Messages 与 API Payload

大家好，今天是我学习 AI Agent 的第十一天。

前十天我主要理解模型本身。从第十一天开始，我正式进入 Agent 核心机制。

今天学的第一个东西，是 messages 数组。

一开始我以为，跟 AI 对话就是把一句话发给模型，然后模型回一句话。

但今天我发现，真实 API 调用不是这么简单。

模型看到的不是单独一句用户输入，而是一组 messages。

每条 message 都有一个 role。

常见 role 有：

system。  
user。  
assistant。  
tool。

system 可以理解成最高优先级规则。  
user 是用户说的话。  
assistant 是模型之前回复过的话。  
tool 是工具返回给模型的结果。

所以一次对话，不只是当前这句话，而是一整段上下文历史。

今天我最大的收获是：

**Agent 的记忆感，很多时候不是模型真的记住了，而是我们把历史 messages 一起发给了它。**

Day 11 的总结是：

**Agent 首先是一种消息组织方式。你怎么组织 messages，模型就怎么理解当前任务。**

今天最重要的三句话是：

第一，模型 API 看到的是 messages 数组。  
第二，system、user、assistant、tool 各自承担不同角色。  
第三，Agent 的稳定性，很大程度来自清晰的消息结构。

## Day 12：上下文管理

大家好，今天是我学习 AI Agent 的第十二天。

昨天我学了 messages，知道模型看到的是一组对话消息。

今天我继续往下学：上下文管理。

一开始我以为，既然 Agent 要记住用户说过什么，那把所有历史对话一直往后追加不就行了吗？

今天我发现，这样做很危险。

因为模型的上下文窗口不是无限的。

system prompt、用户输入、历史回复、工具返回结果、RAG 检索内容，最后都会变成 token，放进上下文窗口里。

如果一直追加，上下文会越来越长。

带来的问题至少有三个：

成本越来越高。  
速度越来越慢。  
重要信息可能被挤掉。

所以 Agent 不能只靠无限追加聊天记录。

它必须学会上下文管理。

比如：

只保留最近几轮对话。  
把旧对话压缩成摘要。  
用滑动窗口控制长度。  
把长期知识放进记忆或向量库，需要时再检索。

今天我最大的收获是：

**一个好的 Agent，不是记得越多越好，而是知道什么时候该记、什么时候该忘、什么时候该检索。**

Day 12 的总结是：

**messages 不能无限增长，必须被管理。**

今天最重要的三句话是：

第一，上下文窗口不是无限记忆。  
第二，历史消息、工具结果、RAG 内容都会消耗 token。  
第三，好的 Agent 要会保留重点、压缩旧信息、检索长期知识。
